# 第 03 章：用 bevy_immediate 创建第一块界面

[上一章](/game/rust/bevy-immediate/bevy-ecs) · [目录](/game/rust/bevy-immediate/main) · [下一章](/game/rust/bevy-immediate/counter)

## 本章目标

学会四个调用：注册插件、建立上下文、描述节点、描述子节点。

完整源码：[lesson03_immediate.rs](/game/rust/bevy-immediate/examples/lesson03-immediate)。运行：

```bash
cargo run --manifest-path Doc/tutorial/Cargo.toml --bin lesson03_immediate
```

预期看到深色背景和两行文字。窗口不会每帧增加新的文字。

## 1. 先读完整的构建函数

下面是完整程序中的 `draw_ui` 函数，其他初始化代码保留在源码里：

```rust
fn draw_ui(ctx: ImmCtx<CapsUi>) {
    let mut ui = ctx.build_immediate_root("lesson03");
    ui.ch_id("panel").on_spawn_insert(panel).add(|ui| {
        ui.ch_id("title").text("Hello, bevy_immediate!");
        ui.ch_id("description").text("This code runs every frame.");
    });
}
```

从外到里读：建立名为 lesson03 的构建范围，在下面描述一个 panel 容器，再描述两行文字。

```text
lesson03（构建范围，不会因为这个名字自动创建实体）
└── panel（实体）
    ├── title（实体）
    └── description（实体）
```

## 2. 为什么要注册插件

main 中加入：

```rust
.add_plugins(BevyImmediatePlugin::<CapsUi>::new())
.add_systems(Update, draw_ui)
```

插件负责建立库内部需要的资源、维护逻辑和 UI 能力。`add_systems` 则让 Bevy 每帧执行你的构建函数。这两件事都需要，注册插件本身不会知道你想画什么。

`CapsUi` 是库提供的一组 UI 功能，包含文字、点击等。现在把它当作固定配置使用即可；自定义能力放到第 08 章。

## 3. `ImmCtx` 是工具包

`ctx: ImmCtx<CapsUi>` 是 Bevy 为系统提供的参数，里面封装了命令、实体查询和库内部状态等工具。

`ctx.build_immediate_root("lesson03")` 把工具包变成可描述节点的 `Imm` 上下文。调用按值消耗 ctx，所以这里没有在后面再次使用原变量。

根 ID 需要稳定。不要每帧把当前时间或随机数当根 ID，否则库会不断认为出现了一棵新界面树。

## 4. `.ch_id()` 的意思是“本帧需要这个节点”

`ch` 可以按 child（子节点）记忆：

```rust
ui.ch_id("title")
```

意思是“在当前父级下面，描述标识为 title 的子节点”。第一次需要时创建，后续能找到就复用。

`"title"` 是用于识别身份的 ID；`"Hello, bevy_immediate!"` 是显示内容，两者是不同概念。改内容不必改 ID。

本教程前几章统一使用显式 ID，方便观察。自动编号 `.ch()` 后面再比较。

## 5. `.on_spawn_insert()` 只处理初始化

```rust
.on_spawn_insert(panel)
```

`panel` 是公共辅助函数，返回 Node、BackgroundColor 组成的组件组合。它与第 02 章是同一个函数。

这句话表示：“如果这个节点本次是新建的，就调用 panel，排队插入它返回的组件。”

因此它适合设置固定布局。后续修改 Rust 中的 panel 函数，并不会让运行中的旧节点自动重新执行初始化；通常需要重启程序，或专门使用动态更新方法。

这里也解释一个常见误会：构建函数每帧执行，不代表链条上每一个回调都每帧执行。

## 6. `.add()` 暂时进入子节点范围

```rust
.add(|ui| {
    ui.ch_id("title").text("Hello");
});
```

闭包里的 `ui` 是容器内部的构建上下文。闭包结束后，后续调用重新回到原来的父级范围。

有同名变量不代表它们是同一个“层级”。参数名只是局部名字，真正的当前父级由上下文管理。

## 7. `.text()` 负责持续同步文字

`.text(...)` 在新节点上添加文字，在已有节点上比较并更新文字。相同文本不需要反复写入。

调用这个方法需要导入 trait：

```rust
use bevy_immediate::ui::text::ImmUiText;
```

trait 导入就是让扩展方法进入当前文件的方法查找范围。

## 8. 两帧之间发生了什么

| 时刻 | 行为 |
|---|---|
| 第一帧描述 panel | 没找到对应实体，排队创建 |
| 第一帧描述 title | 排队创建文字子实体 |
| 命令应用后 | 实体和组件真正进入 World，ID 映射被维护 |
| 下一帧描述同样的 ID | 找回旧实体，标记本帧仍需要它 |

目前只需要知道 ID 能找回实体。第 07 章会亲手写一个小模型验证。

## 练习与预期

在闭包里新增：

```rust
ui.ch_id("third-line").text("I added this line myself.");
```

重启后应出现第三行。再把它删掉并重启。接下来一章会让内容在运行过程中变化，从而看到“每帧描述”的用途。
