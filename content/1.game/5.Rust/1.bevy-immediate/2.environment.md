# 第 00 章：先把环境和文件位置弄清楚

[目录](/game/rust/bevy-immediate/main) · [下一章：Rust 必备基础](/game/rust/bevy-immediate/rust-basics)

## 本章目标

知道哪个文件是入口、在哪里运行命令，以及出现环境问题时先查什么。

## 1. 我们创建了什么

原项目是一个库：它提供可以被别人调用的功能。我们需要一个应用程序，才能开窗口使用这个库。

本教程已经建立了应用工程：

```text
bevy_immediate/                 ← 原仓库根目录
├── Cargo.toml                  ← 原库和 workspace 的配置
├── crates/                     ← 原库实现
└── Doc/
    ├── README.md               ← 教程入口
    └── tutorial/               ← 本教程的应用工程
        ├── Cargo.toml          ← 教学应用的配置
        ├── Cargo.lock          ← 记录依赖解析结果
        └── src/
            ├── lib.rs          ← 公共外观辅助函数
            └── bin/
                ├── lesson01_window.rs
                ├── lesson02_bevy_ui.rs
                └── ...
```

一个普通 Rust 应用也可以只用 `src/main.rs`。这里使用 `src/bin/文件名.rs`，是为了让每一课都成为独立入口。运行某一课时，其他课的 `main()` 不会一起执行。

## 2. 检查 Rust 工具链

在终端执行：

```bash
rustc --version
cargo --version
```

`rustc` 是编译器，负责把 Rust 源码转换成机器可以执行的程序。`cargo` 负责组织工程、下载依赖、调用编译器和运行程序。

当前根项目要求 Rust 至少为 1.97.1。版本低于要求时，先通过你安装 Rust 时使用的工具链管理方式升级；使用 rustup 的环境可以执行 `rustup update stable`。如果还没安装 Rust，需要先完成系统对应的 Rust 安装。

首次构建 Bevy 需要下载并编译许多依赖，耗时和磁盘占用会明显多于普通控制台程序。Linux 图形应用还需要系统的编译工具、窗口系统相关开发库和可工作的显卡驱动；缺少这些时，通常会在编译日志中看到具体的库名或 `pkg-config` 错误。优先根据真实报错处理，不要先盲目改 Rust 代码。

## 3. 看懂最关键的工程配置

下面是 [完整 Cargo.toml](/game/rust/bevy-immediate/examples/cargo-toml) 中的片段：

```toml
[package]
name = "bevy_immediate_tutorial"
version = "0.1.0"
edition = "2024"

[workspace]

[dependencies]
bevy_immediate = { path = "../.." }
```

- `[package]` 描述这个工程的名字、版本和 Rust 语法版本。
- 空的 `[workspace]` 让教学工程独立管理，避免 Cargo 把它误认为上层 workspace 中一个未登记的成员。
- `path = "../.."` 相对于这个 `Cargo.toml` 所在目录，指向原仓库根目录。它表示使用本地源码。
- 另外一条 `bevy` 依赖声明了窗口、文字、UI 渲染和点击检测等功能；完整文件已经提供，无需自己拼写。

`features` 可以理解为依赖的功能开关。比如没有 UI 渲染功能，拥有 UI 数据也不等于能把它显示出来。前几章先沿用配置，后面再考虑裁剪功能。

## 4. 三种常用命令

只检查是否能够通过编译：

```bash
cargo check --manifest-path Doc/tutorial/Cargo.toml --bins
```

运行某一课：

```bash
cargo run --manifest-path Doc/tutorial/Cargo.toml --bin lesson01_window
```

检查代码格式：

```bash
cargo fmt --manifest-path Doc/tutorial/Cargo.toml --check
```

`--manifest-path` 告诉 Cargo 使用哪个工程；`--bin` 告诉它运行哪个入口。关闭窗口就会结束窗口程序。

如果先进入了 `Doc/tutorial`，命令可以简写为：

```bash
cargo run --bin lesson01_window
```

后续章节统一使用从仓库根目录执行的完整命令。

## 5. 可选：复用已有构建目录

教学工程默认把构建结果放在 `Doc/tutorial/target`。如果原仓库已经构建过，Linux/macOS 的 shell 中可以这样尝试复用根目录缓存：

```bash
CARGO_TARGET_DIR=target cargo check --manifest-path Doc/tutorial/Cargo.toml --bins
```

不同功能组合仍可能触发重新编译。这个环境变量只影响构建结果的位置，不影响代码逻辑。Windows 的环境变量写法不同，可以直接使用前面的通用 Cargo 命令。

## 本章检查

你应该能够说清楚：`Cargo.toml` 是配置文件，`.rs` 是源码文件，`cargo run --bin ...` 选择一个入口。现在还不需要理解 UI 是怎么画出来的。
