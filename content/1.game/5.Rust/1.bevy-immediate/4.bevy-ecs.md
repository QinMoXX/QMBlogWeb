# 第 02 章：从一个窗口到 Bevy 的数据组织方式

[上一章](/game/rust/bevy-immediate/rust-basics) · [目录](/game/rust/bevy-immediate/main) · [下一章](/game/rust/bevy-immediate/first-ui)

## 本章目标

先用普通 Bevy 做出计数器，知道 bevy_immediate 帮我们省掉了哪些管理工作。

## 1. 第一个窗口

运行：

```bash
cargo run --manifest-path Doc/tutorial/Cargo.toml --bin lesson01_window
```

完整程序只有这些内容：

```rust
use bevy::prelude::*;

fn main() {
    App::new()
        .add_plugins(DefaultPlugins)
        .add_systems(Startup, setup)
        .run();
}

fn setup(mut commands: Commands) {
    commands.spawn(Camera2d);
}
```

逐行理解：

- `use bevy::prelude::*` 导入 Bevy 常用类型，不是启动引擎。
- `App::new()` 创建应用配置对象。
- `DefaultPlugins` 安装当前启用功能对应的基础插件，包括窗口、输入、渲染等。
- `add_systems(Startup, setup)` 登记启动时运行的函数；这里传递的是函数，没写 `setup()`。
- `run()` 开始事件循环，应用会持续处理输入、更新和绘制。
- `commands.spawn(Camera2d)` 排队创建一个带有 2D 相机组件的实体。

现在只应看到一个空窗口。相机为后续显示 UI 准备观察入口；创建它不会自动生成文字或按钮。

这里的连续 `.方法()` 叫链式调用，效果是把配置一步步加到 App 上。

## 2. ECS 是怎样看待一个计数器的

想象我们需要“计数数据”和“一行显示数据的文字”。可以把世界看成一张简化表：

| 身份编号 | 身上有哪些组件 |
|---|---|
| 实体 A | `Camera2d` |
| 实体 B | `Node`、背景颜色 |
| 实体 C | `Text`、`CounterLabel` |

Entity 是身份编号，Component 是附加的数据。一个实体可以有多个不同类型的组件。

`CounterLabel` 可以没有字段，仅用于标识“这行文字是计数器文字”。它就像一张标签。

Resource 是另外一种组织方式：按类型保存应用共享数据。本课只有一份全局计数，所以用 `Counter` 资源。

System 是处理这些数据的函数。例如“读空格键并增加计数”和“把计数写进文字”是两个系统。

## 3. 普通 Bevy UI 计数器

打开完整源码 [lesson02_bevy_ui.rs](/game/rust/bevy-immediate/examples/lesson02-bevy-ui)，运行：

```bash
cargo run --manifest-path Doc/tutorial/Cargo.toml --bin lesson02_bevy_ui
```

预期看到提示和 `Count: 0`。把焦点放在窗口里，每按一次空格，数值加一。按住空格不会每帧增加，因为使用的是 `just_pressed`。

### 第一步：声明数据

```rust
#[derive(Component)]
struct CounterLabel;

#[derive(Resource, Default)]
struct Counter {
    value: u32,
}
```

`struct CounterLabel;` 是没有字段的结构体。`Default` 让 Counter 默认从零开始。声明类型本身不会把数据放进 World，仍需要初始化或创建实体。

### 第二步：把资源和系统放进 App

```rust
.init_resource::<Counter>()
.add_systems(Startup, (camera, setup))
.add_systems(Update, (read_keyboard, update_label).chain())
```

这是 main 中的片段：

- `init_resource::<Counter>()` 在尚不存在时创建默认 Counter 资源。`::<...>` 是显式提供泛型参数的写法。
- `Startup` 在应用的启动流程执行。
- `Update` 在通常的每帧更新流程执行。
- `.chain()` 明确让读键盘先于更新文字。单纯把系统放进一个元组，并不等于承诺从左到右执行。

### 第三步：创建文字实体

```rust
commands.spawn(panel()).with_children(|parent| {
    parent.spawn((Text::new("Press Space to add one"), TextFont::default()));
    parent.spawn((CounterLabel, Text::new("Count: 0"), TextFont::default()));
});
```

`panel()` 返回一个容器的组件组合。`with_children` 在容器下面创建两个子实体。文本自身和布局容器都有所需的关联组件，Bevy 会根据组件要求补齐一些默认数据；我们只显式设置当前需要关心的部分。

这些代码只在 `Startup` 运行，所以不会每帧创建两行新文字。

### 第四步：读取输入、修改资源

```rust
fn read_keyboard(keys: Res<ButtonInput<KeyCode>>, mut counter: ResMut<Counter>) {
    if keys.just_pressed(KeyCode::Space) {
        counter.value += 1;
    }
}
```

`Res<T>` 表示读取资源，`ResMut<T>` 表示允许修改资源。这是 Bevy 提供的访问包装，并不完全等同于普通 `&T`、`&mut T`，但当前可以用类似的方式理解权限。

你没有手动调用这个函数。Bevy 根据参数类型从 World 准备数据，再执行它。合法的这种系统参数通常实现了 `SystemParam`。

### 第五步：查询文字并更新

```rust
fn update_label(counter: Res<Counter>, mut labels: Query<&mut Text, With<CounterLabel>>) {
    for mut text in &mut labels {
        let next = format!("Count: {}", counter.value);
        if text.0 != next {
            text.0 = next;
        }
    }
}
```

把 Query 读成一句话：“找出带有 CounterLabel 的实体，给我它们的可变 Text。”

`With<CounterLabel>` 是过滤条件。`text.0` 表示访问 Text 这个元组结构体的第一个字段。写入前先比较内容，避免相同文本反复触发变化。

## 4. 布局的四个基本词

公共 `panel()` 放在 [lib.rs](/game/rust/bevy-immediate/examples/lib)，主要设置：

| 属性 | 含义 |
|---|---|
| `width`、`height` | 宽、高；百分比相对于布局上下文 |
| `flex_direction: Column` | 子节点纵向排列 |
| `padding` | 容器边缘到内容的内边距 |
| `row_gap` | 这里用于纵向子项间的间隔 |

`Val::Px(24.0)` 表示布局像素值，`Val::Percent(100.0)` 表示百分比。

先做实验：把 `Column` 改为 `Row`，再把 `row_gap` 改成 `column_gap`，观察两行文字如何横向排列。完成后恢复。

## 5. 到这里已经理解了什么

普通写法把工作分开：启动时创建文字，更新时查询文字，再把业务值写进去。如果界面还有动态分支和列表，我们还得管理哪些实体该创建、删除以及重排。

下一章会把界面描述集中到一段每帧运行的代码里，而 Counter 的业务数据仍需要保存在资源或组件中。
