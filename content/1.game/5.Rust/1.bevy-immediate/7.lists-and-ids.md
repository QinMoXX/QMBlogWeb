# 第 05 章：让节点出现、消失和重排

[上一章](/game/rust/bevy-immediate/counter) · [目录](/game/rust/bevy-immediate/main) · [下一章](/game/rust/bevy-immediate/attach)

## 本章目标

做出可添加、删除和倒序的列表，真正理解 ID 与显示内容的区别。

完整源码：[lesson05_list.rs](/game/rust/bevy-immediate/examples/lesson05-list)。运行：

```bash
cargo run --manifest-path Doc/tutorial/Cargo.toml --bin lesson05_list
```

操作顺序：点三次 Add item，点一次 Reverse order，再点击任意条目。最后点 Toggle help 两次。

预期：出现三个条目、倒序、被点击的条目消失；说明文字可以显示和隐藏。

## 1. 把数据模型写清楚

```rust
struct Item {
    id: u64,
    title: String,
}

#[derive(Resource, Default)]
struct ListState {
    next_id: u64,
    items: Vec<Item>,
    show_help: bool,
}
```

`Vec<Item>` 保存条目。`next_id` 记录下一条新数据的身份编号。`show_help` 是是否显示说明的开关，bool 只有 true 和 false。

Item 不需要成为 Bevy 组件：本课把所有条目作为普通 Rust 数据放在一个资源里，界面再根据数据生成。

添加条目的片段：

```rust
let id = state.next_id;
state.next_id += 1;
state.items.push(Item {
    id,
    title: format!("Item {id} (click to remove)"),
});
```

先把编号存到局部变量，再修改字段和 push，代码更容易读，也避免在同一个复杂表达式中混合多个访问。

删除条目以后不会回退 next_id，因此新条目不会立刻冒用旧条目的 ID。本课不处理计数器最终溢出的极端情况。

## 2. 显示条件就是一个 if

```rust
if state.show_help {
    ui.ch_id("help-text").text("Add items, reorder them, or click one to remove it.");
}
```

当值为 true，执行这段描述；为 false，不执行。

库会把“这一轮没有再描述的受管理节点”清理掉，所以业务代码不用另外保存 help 实体并调用删除。

这里隐藏意味着对应界面实体会被删除。再次显示会创建新的实体，挂在该实体上的临时组件状态也会重新开始。需要保存的数据应放在仍然存在的资源或其他组件中。

## 3. 列表中的身份应该来自数据

```rust
for item in &state.items {
    let mut row = ui.ch_id(("item", item.id))
        .on_spawn_insert(button)
        .add(|ui| {
            ui.ch_id("caption").text(item.title.as_str());
        });
    // 点击处理略，见完整源码
}
```

`("item", item.id)` 是一个元组，整个元组都参与生成 ID。`"item"` 区分节点类别，`item.id` 区分具体条目。

`item.title.as_str()` 从 String 借用字符串片段。`.text()` 在需要拥有字符串内容时会转换为 String，你不需要每次手动 clone 整个 Item。

倒序改变的是 Vec 中的排列，不会改变每条数据的 id。

| 当前顺序 | 数据 ID | 对应实体身份 |
|---|---:|---|
| 倒序前第一个 | 0 | A |
| 倒序前第二个 | 1 | B |
| 倒序后第一个 | 1 | 仍为 B |
| 倒序后第二个 | 0 | 仍为 A |

库另外维护 UI 子节点顺序，使布局顺序跟随当前描述顺序。身份和排列是两个不同的问题。

## 4. 为什么不直接用下标

假设原列表是 Alice、Bob，下标分别是 0、1。删除 Alice 后，Bob 变成下标 0。

如果 ID 来自下标，Bob 就可能接手原来编号 0 的界面实体。单纯文字也许还能被覆盖成正确值，但焦点、输入状态、初始化数据等可能跟错对象。

稳定 ID 表达“这是谁”，下标表达“现在排在哪”。动态列表通常应该使用前者。

## 5. `.ch()` 和 `.tch()` 可以什么时候用

| 写法 | 如何识别节点 | 适用情况 |
|---|---|---|
| `.ch()` | 当前范围内自动递增编号 | 数量和调用顺序固定 |
| `.ch_id(value)` | 显式值结合当前范围 | 条件节点、动态列表 |
| `.tch()` | 调用位置结合当前范围 | 固定位置的独立调用 |

循环里的 `.tch()` 每轮都位于同一个源码位置，所以仍需要为每轮增加区别。可以这样写：

```rust
for item in &state.items {
    let mut scoped_ui = ui.with_add_id_pref(item.id);
    scoped_ui.tch().text(item.title.as_str());
}
```

这是替代列表描述的片段，不需要同时保留前面那套 row。`with_add_id_pref` 提供临时 ID 前缀，作用域退出时自动恢复。

同级节点的 ID 必须区分开。不同父节点下都叫 `"caption"` 则可以，因为父级范围也参与生成 ID。

## 6. 删除为什么分成两步

程序先记录，再修改：

```rust
let mut remove_id = None;
for item in &state.items {
    // 构建 row
    if row.clicked() {
        remove_id = Some(item.id);
    }
}
if let Some(id) = remove_id {
    state.items.retain(|item| item.id != id);
}
```

这是省略构建部分的解释片段。`retain` 保留闭包返回 true 的条目。

遍历 `&state.items` 时有共享借用。如果此时直接删除 Vec 的元素，会修改正在被遍历的结构。记录编号、等遍历结束再删除，就把两种访问分开了。

注意执行时机：被点击的 row 在本次循环里已经被描述过。因此数据在当前调用末尾删除后，该 row 通常要到下一次构建不再被描述时才被清理。这不是数据删除失败，而是代码顺序的结果。

## 自测

把某条数据的 title 改成别的文字但保留 id，它应仍对应同一实体。把列表反转，它应换位置但保留身份。把数据删除后重新用全新的 id 添加，应得到新的身份。
