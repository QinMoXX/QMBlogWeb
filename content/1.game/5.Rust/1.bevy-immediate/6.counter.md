# 第 04 章：让按钮真正修改计数

[上一章](/game/rust/bevy-immediate/first-ui) · [目录](/game/rust/bevy-immediate/main) · [下一章](/game/rust/bevy-immediate/lists-and-ids)

## 本章目标

完成 +1、Reset 和数值显示，并理解状态、输入、界面描述三者的关系。

完整源码：[lesson04_counter.rs](/game/rust/bevy-immediate/examples/lesson04-counter)。运行：

```bash
cargo run --manifest-path Doc/tutorial/Cargo.toml --bin lesson04_counter
```

预期：点击 `+1` 增加数值；点击 `Reset` 恢复为零。

## 1. 数值为什么不能只放在构建函数里

如果写成：

```rust
fn draw_ui(/* 参数省略 */) {
    let mut count = 0;
    // 点击后修改 count
}
```

这是错误思路的示意片段：函数下一次运行，又从零创建局部变量。构建函数不会自动保存普通局部变量。

本课继续把业务值放在资源里：

```rust
#[derive(Resource, Default)]
struct Counter {
    value: u32,
}
```

main 用 `.init_resource::<Counter>()` 初始化。系统参数用 `mut counter: ResMut<Counter>` 获取修改权。只要资源存在，下一帧仍能读到之前的值。

## 2. 按钮由外层节点和文字子节点组成

```rust
let mut add = ui.ch_id("add").on_spawn_insert(button).add(|ui| {
    ui.ch_id("caption").text("+1");
});
```

外层实体负责按钮区域，子实体负责显示文字：

```text
add：Button、Node、BackgroundColor、Hovered
└── caption：Text
```

公共 [button()](/game/rust/bevy-immediate/examples/lib) 返回的组件组合包含：

- `bevy::ui_widgets::Button`：Bevy 内建按钮控件组件。
- `Hovered`：指针悬停相关数据，与原项目按钮示例的配置一致。
- `Node`：这里设置内边距，让文字周围有可点击区域。
- `BackgroundColor`：提供蓝色背景。

教学按钮没有额外的悬停变色系统。它能点击，不代表外观一定会在悬停时变化；外观行为需要单独实现。

## 3. 为什么变量是 `let mut add`

`.ch_id()` 返回 `ImmEntity`，可以理解为“本次构建期间操作某个实体的把手”。我们把它命名为 add。

`.clicked()` 接收 `&mut self`，因为必要时它要排队给实体添加点击追踪标记。因此局部变量需要 `mut`。

```rust
if add.clicked() {
    counter.value += 1;
}
```

这个 if 是普通 Rust 条件判断。你不用在业务代码里另外注册一个点击观察器，库已经把点击记录包装成可查询的布尔结果。

还要导入 trait：

```rust
use bevy_immediate::ui::clicked::ImmUiClicked;
```

## 4. 点击检测的简化流程

```text
输入系统产生指针点击事件
        ↓
库的观察器记录被点击的已追踪实体
        ↓
构建函数调用 add.clicked()
        ↓
修改 Counter 资源
        ↓
.text(format!(...)) 同步数值
```

点击记录不是永久的，库会在每帧开始阶段清空记录。`.clicked()` 首次用于节点时会补上追踪标记，那个尚未注册的调用返回 false。不要把它理解成“查询按钮历史上有没有被点过”。

`.clicked()` 判断是否记录了指针点击；只想响应主键可以使用 `.primary_clicked()`。Bevy widgets 的 `.activated()` 读取的是控件激活事件，和指针点击属于不同接口。本课先学会 `.clicked()`。

## 5. 代码顺序也影响显示时机

程序把显示计数的代码放在按钮处理之后：

```rust
if add.clicked() {
    counter.value += 1;
}
// Reset 的处理也在这之前
ui.ch_id("value").text(format!("Count: {}", counter.value));
```

这样本次调用 `.text()` 时就能使用更新后的数值。

如果把文字描述放在修改之前，文字使用的是本次修改前的值，后续构建才反映变化。构建函数会重复运行，但它内部仍按普通 Rust 语句顺序执行。

## 6. 创建组件为什么不一定马上可读

Bevy 的 `Commands` 通常把结构性修改排队，等命令应用时执行。刚描述出来的新实体，可能还不能通过查询读到组件。

因此不要期待下面这类思路总成立：“刚排队插入组件，下一句查询就一定能得到它”。库的文字和点击能力都为新节点准备了补充路径。

当前阶段直接使用这些方法即可，第 08 章自己写扩展时再处理这一细节。

## 小练习

复制 Reset 按钮结构，把 ID 改为 `"minus"`、文字改为 `"-1"`，点击时执行：

```rust
counter.value = counter.value.saturating_sub(1);
```

`saturating_sub` 在零时仍返回零。因为 `u32` 不表示负数，这比直接 `-= 1` 更符合本课“最低为零”的行为。

预期：先加三次，再减四次，结果应为零；每个按钮的同级 ID 都不同。
