# 第 06 章：把一块界面变成可复用组件

[上一章](/game/rust/bevy-immediate/lists-and-ids) · [目录](/game/rust/bevy-immediate/main) · [下一章](/game/rust/bevy-immediate/mini-core)

## 本章目标

只写一份计数器构建代码，创建两个各自独立的计数器。

完整源码：[lesson06_attach.rs](/game/rust/bevy-immediate/examples/lesson06-attach)。运行：

```bash
cargo run --manifest-path Doc/tutorial/Cargo.toml --bin lesson06_attach
```

预期：两个面板分别从 0、100 开始，点击左边不会改变右边。

## 1. 为什么要把状态移到组件里

第 04 章使用一份 Counter 资源，所以所有读取它的界面都会看到同一个数值。

本章希望每个面板有自己的数值，于是改为：

```rust
#[derive(Component)]
struct CounterRoot {
    value: u32,
}
```

创建两份实体，各有自己的 CounterRoot 组件。类型相同不代表数据只有一份；每个实体都可以拥有该类型的一份组件。

```text
根实体 A：CounterRoot { value: 0 }
├── +1 按钮
└── 数值文字

根实体 B：CounterRoot { value: 100 }
├── +1 按钮
└── 数值文字
```

## 2. attach 就是挂到已有实体下面

前面使用 `build_immediate_root` 从没有父实体的范围开始构建。

这里先通过 Commands 创建面板实体，再让库在面板下面构建子节点。

注册代码：

```rust
.add_plugins(BevyImmediateAttachPlugin::<CapsUi, CounterRoot>::new())
```

把尖括号里的内容读成：“使用 CapsUi 能力，对带 CounterRoot 的实体执行挂载构建。”

这个插件会负责确保核心插件已经添加，不需要再手动添加一份同能力的核心插件。

## 3. 告诉库怎么构建

```rust
impl ImmediateAttach<CapsUi> for CounterRoot {
    type Params = CounterParams<'static, 'static>;

    fn construct(ui: &mut Imm<CapsUi>, params: &mut CounterParams) {
        // 实际代码见源码
    }
}
```

这是 trait 实现片段。它定义了 CounterRoot 对应的构建规则。

`type Params = ...` 是“关联类型”：告诉这份实现需要哪种系统参数。它不是在函数里新建变量。

构建方法没有 `&self`，所以不会直接收到当前的 CounterRoot 数据。需要通过根实体身份，配合查询拿到对应组件。

## 4. 参数结构体里放查询

```rust
#[derive(SystemParam)]
struct CounterParams<'w, 's> {
    roots: Query<'w, 's, &'static mut CounterRoot>,
}
```

先读业务部分：这个参数提供“可修改 CounterRoot 的查询”。`SystemParam` 派生让 Bevy 能为这个组合参数准备数据。

生命周期标记现在这样理解即可：

- `'w`、`'s` 表达这些借用与 World、系统参数状态的有效期关系。
- 字段声明中的 `&'static mut CounterRoot` 是 Bevy 查询类型的描述写法。
- 关联类型中的 `'static` 是声明参数类型的模板，实际执行时 Bevy 通过 `SystemParam::Item` 提供当前运行期的借用。

**这不表示获得了一份可以永久持有的可变组件引用。** 初学时不要为了消除报错就到处添加 `'static`，应先沿用这个模板。

## 5. 找到当前这一份状态

```rust
let root_entity = ui.current_entity().expect("attach supplies a root entity");
let mut state = params.roots.get_mut(root_entity).expect("root exists");
```

第一句取得当前面板实体；第二句查询该实体上的 CounterRoot。

`Option::expect` 在没有值时终止并显示消息；`Result::expect` 在错误时也会终止。这里因为执行路径就是 attach 为根实体调用构建，示例使用 expect 让假设清楚可见。其他不保证存在的查询可以用 `if let Ok(...)` 等方式处理。

之后的按钮逻辑与第 04 章相同，只是修改对象从全局资源变成该面板组件。

## 6. 两边都有 `"add"`，为什么不冲突

attach 生成的根范围会结合根组件类型、能力类型和具体根实体身份。

因此左侧的 `"add"` 与右侧的 `"add"` 位于不同根范围，最终 ID 不同。同一个面板内部的同级节点仍需要不同 ID。

## 7. 现在有哪些复用方法

| 方式 | 如何调用 | 状态通常放哪里 |
|---|---|---|
| 普通函数 | 在已有构建函数里调用 `draw_part(ui, ...)` | 由参数传入 |
| attach 组件 | 给实体添加对应根组件 | 根组件或查询到的业务数据 |

原仓库的 [widget_functional.rs](/game/rust/bevy-immediate/sources/examples-widget-functional-rs) 和 [widget_native.rs](/game/rust/bevy-immediate/sources/examples-widget-native-rs) 分别展示了这两种方式。

普通函数适合先把一段重复代码提取出来；当你希望通过“给实体添加组件”来启用界面，attach 很合适。
